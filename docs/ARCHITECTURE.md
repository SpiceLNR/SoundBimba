# SoundBimba — архитектура (v0.1, черновик для согласования)

Нодовая среда маршрутизации звука для Windows 11: перехватить звук приложения, направить в
виртуальный микрофон и в наушники, добавить свой микрофон и кнопки-звуки. Аналог по назначению
Voicemeeter + Soundpad, но с картой-схемой и интерфейсом «для обычного человека».

Автор проекта не программист. Все решения ниже согласованы с ним в переписке; изменения — только
с его согласия.

---

## 1. Принятые решения

| Тема | Решение |
|---|---|
| Платформа | Windows 11 x64 (проверено на 24H2, сборка 26100, LTSC IoT, пользовательская сборка «SpicePC») |
| Работа | Полностью офлайн: никакой телеметрии, CDN, автообновлений, сетевых запросов при работе |
| Стек | Tauri 2 + Rust (звук и ядро), React + React Flow (xyflow) для карты |
| Лицензия | **AGPL-3.0-or-later** |
| Виртуальный микрофон | Виртуальный кабель, который пользователь ставит сам (рекомендуем VB-CABLE с официального сайта). Приложение драйвер **не встраивает**, только находит и подсказывает, как поставить. **Свой драйвер пока не пишем** (этап 8). Решение от 2026-11-02, см. раздел 7 |
| Подпись релизов | SignPath Foundation (бесплатно для OSS, требует OSI-лицензию — AGPL подходит). Заявка подаётся ближе к релизу |
| Репозиторий | Публичный на GitHub. Без приватных репозиториев и платных функций (ограничения GitHub для региона автора) |
| Языки интерфейса | Русский, английский, украинский с первого дня |
| Горячие клавиши | Только внутри окна приложения, все переназначаемые (окно «Клавиши»), в полях ввода не срабатывают. Глобальных нет — конфликты с играми и античитами (решение от 2026-11-02) |
| Звук приложения | Копия (захват по процессу). Оригинал продолжает играть у пользователя как раньше. Управление мониторингом — этап 2 |
| Несколько проводов в один вход | Звук складывается (как соединение проводов). Узла «Микшер» нет |
| Громкость, шумоподавление, эффекты | Отдельные узлы, не свойства других узлов |
| Темы | По порядку: «Бимба» (по умолчанию), «Метро», «Детская» (флеш-игра нулевых, Comic Sans из Windows), «Нео-нуар» (на основе «Бимбы»: неон, мерцание), «Инженерская» (на основе «Метро»: печатная плата), «Фрутигер аэро» (синее небо и луг, голубое стекло, глянец, пузыри; Segoe UI из Windows). Порядок — поле `order` в `theme.json` |
| Android | Отдельный проект SoundBimbaLite, не в этом репозитории |

## 3. Модель графа (файл проекта)

JSON с номером версии схемы. Автосохранение в `%APPDATA%\SoundBimba\project.json`, экспорт и
импорт — вручную. Узлы не знают о звуке, граф можно открыть и без драйвера. Повреждённый файл
не удаляется: откладывается как `project.broken-<дата>.json`, открывается новый проект. Настройки
интерфейса (язык, тема) — отдельно, в `settings.json` рядом.

```json
{
  "schema": 1,
  "nodes": [
    {"id": "n1", "type": "app-source",   "pos": [0, 0],    "params": {"exe": "discord.exe"}},
    {"id": "n2", "type": "mic-input",    "pos": [0, 160],  "params": {"device": "default"}},
    {"id": "n3", "type": "volume",       "pos": [260, 0],  "params": {"gain": 1.0, "mute": false}},
    {"id": "n4", "type": "virtual-out",  "pos": [520, 60], "params": {"device": "virtual-1"}}
  ],
  "edges": [
    {"from": "n1", "to": "n3"},
    {"from": "n2", "to": "n4"},
    {"from": "n3", "to": "n4"}
  ]
}
```

Правила: циклы запрещены (UI не даёт соединить); выход может идти в несколько входов; вход может
принимать несколько проводов (сумма). Типы портов: сейчас только «звук»; тип «управление»
заложить в модель, но не показывать до появления узлов, которым он нужен.

**Свои шаблоны — файлы `.bmb`** (решение автора 2026-11-02), JSON с меткой формата, чтобы чужой
файл с тем же расширением не приняли: `{"format": "soundbimba-template", "version": 1, "name",
"description", "project": <проект как выше>}`. Лежат в `%APPDATA%\SoundBimba\templates\`;
сохраняются из текущей карты, открываются из файла или двойным щелчком (установщик связывает
`.bmb` с SoundBimba для текущего пользователя, удаление программы связь снимает), удаляются с
подтверждением. Программа запускается в одном экземпляре: второй запуск передаёт файлы первому.

## 5. Аудио-движок

- Одна частота дискретизации на весь граф (48 кГц, float32, стерео). Передискретизация только на
  краях (устройства, файлы).
- Низкая задержка: WASAPI shared, event-driven; где доступно — IAudioClient3 с минимальным
  периодом. Цель сквозной задержки < 30 мс, измерять, а не гадать.
- Поток реального времени: без выделения памяти, без блокировок, без ввода-вывода внутри
  обработки. Связь с UI через неблокирующие очереди команд.
- Граф перед запуском «компилируется» в топологический порядок и массив буферов.
- **Как сделано (этап 2):** `crates/engine` — граф, сложение, громкость с плавным изменением,
  кольцевые буферы (`rtrb`) с подстройкой скорости (кубическая интерполяция, поправка до ±0,5 %);
  `crates/winaudio` — потоки устройств (событийный WASAPI shared; где можно — IAudioClient3 с
  минимальной порцией) и поток движка (блок 5 мс, высокоточный таймер, MMCSS «Pro Audio»).
  Изменение проводов/устройств перезапускает движок и потоки (короткая пауза), изменение громкости
  применяется на лету. Устройства и программы проверяются раз в 2 секунды (переподключение).
- Разные устройства имеют разные часы: между ними нужны кольцевые буферы с компенсацией дрейфа
  (адаптивная передискретизация), иначе будут щелчки со временем.
- Захват приложения: Windows process loopback (`AUDIOCLIENT_ACTIVATION_TYPE_PROCESS_LOOPBACK`,
  режим include process tree; Windows 10 build 20348+, у нас 26100). Если у процесса нет
  активных потоков вывода, приходит тишина — это норма, показать в UI «приложение молчит».
- Видеокарта для звука не используется (пересылка в GPU дороже самой обработки). Нейро-эффекты
  позже — отдельный необязательный узел.

## 6. Интерфейс

**Рабочая среда (режим «эксперт»).** Холст с картой. Принципы «аккуратной карты»:
- авто-раскладка слева направо (источники → обработка → выходы), кнопка «Упорядочить»;
- цвет узла по типу (источники / обработка / выходы / кнопки), порты крупные;
- провод подписан только при наведении; живой индикатор уровня на проводе;
- минимум настроек на узле, остальное — в боковой панели выбранного узла;
- шаблоны одним щелчком («Саундпад в Discord», «Игра в микрофон и наушники», …);
- мини-карта и зум, привязка к сетке.
- Тема «Бимба»: фон поля — едва заметные точки; по центру — едва заметный крупный водяной знак
  «пятачок» (`assets/pignose.svg`, цвет и прозрачность из темы).

**Простой режим.** Только кнопки, пресеты морфера (место под них заложить сразу), регуляторы
громкости с подписью «откуда → куда». Без карты.
*Как сделано (этап 3):* переключатель в «Настройки → Режим»; громкость — узлы «Громкость»
проекта, подпись по соседним узлам; морфер — пустой раздел-заглушка до этапа 6.

**Кнопочная панель.** Отдельное окно (рамка по желанию), поверх остальных, без глобальных горячих клавиш.
В играх на полном экране поверх может не рисоваться — рекомендовать оконный режим без рамки.
*Как сделано (этап 3):* второе окно Tauri (`#buttons`) того же интерфейса, «Настройки → Окна →
Кнопочная панель»; проект и настройки получает событиями `project-changed` / `settings-changed`.
Звуки кнопок (WAV, MP3, OGG, FLAC любой длины, `crates/clips`, symphonia): первые 2 секунды —
в памяти (мгновенный старт), остальное подкачивается с диска отдельным потоком через кольцевой
буфер; перемотка — просьба движка (номер + позиция) и метка в буфере, после которой идут
отсчёты с новой позиции. Всё переводится в 48 кГц стерео; поток звука только копирует отсчёты.
Кнопка: середина — играть / пауза / продолжить (затухание и вступление по 5 мс); в конце трека —
стоп и шкала на начало; кольцо — шкала времени, нажатие на него перематывает (и запускает, если
стояла); после перемотки движок ждёт 0,1 с запаса подкачки, чтобы не было прерываний; внутри —
время «сейчас / всего».

**Темы.** Тема = папка в `themes/<id>/` с `theme.json` (названия на трёх языках, шрифты) и
`theme.css` (переменные: цвета, радиусы, толщины, тени, вид узлов и проводов, при необходимости
SVG-декор). Никаких цветов в коде компонентов — только переменные темы.
- «Бимба»: тёмная, дружелюбная, розовый акцент (#ff1493 с логотипа).
- «Метро»: плоские плитки, без скруглений, крупная лёгкая типографика заглавными, насыщенные
  акцентные цвета. Шрифт Segoe UI поставлять нельзя (лицензия Microsoft) — взять свободный
  аналог (например, Selawik под SIL OFL; проверить лицензию и положить в
  THIRD_PARTY_NOTICES).

**Локализация.** `locales/{ru,en,uk}.json`, ключи вместо строк в коде, запасной язык — английский.
Язык по умолчанию — язык системы.

## 7. Виртуальное устройство (виртуальный кабель)

- Виртуальный кабель — пара устройств: виртуальный динамик (выход) и виртуальный микрофон (вход).
  Приложение пишет сведённый звук в «динамик» кабеля; другие программы (Discord, OBS) выбирают
  «микрофон» кабеля как вход. **Эту связку проверяет прототип** (`probe --loop-test`): доходит ли
  звук, с какой задержкой и в каком формате.
- **Почему не встраиваем драйвер (решение от 2026-11-02).** Изначально планировали
  VirtualDrivers/Virtual-Audio-Driver. Проверка показала: (1) подпись релиза 25.7.14 Windows 11
  не принимает (ошибка 52, issues #13, #15, #16, #23), автору не хватает средств на подпись
  Microsoft; (2) его виртуальный микрофон выдаёт тестовый тон, а не звук «динамика» (issue #5),
  то есть связки нет вовсе. Открытого драйвера с подписью Microsoft и рабочей связкой не нашлось.
  Обходы с `testsigning` или выключенным Secure Boot не предлагаем: это снижает защиту, и игры с
  античитом в таком режиме не запускаются.
- **Как теперь.** Пользователь сам ставит виртуальный кабель с официального сайта (рекомендуем
  VB-CABLE: бесплатный, «плати сколько хочешь», закрытый код). Приложение его не распространяет
  и не изменяет, только **находит по названию устройств** и показывает понятное сообщение, если
  кабеля нет: мастер-подсказка «установите виртуальный кабель» со ссылкой на официальный сайт и
  пошаговой инструкцией. Список известных кабелей — в коде, расширяемый (VB-CABLE, VB-CABLE A/B/C/D
  и др.).
- Имена устройств — те, что дал производитель кабеля. Так и оставляем.
- Больше одного устройства (идея пользователя: до 10) = несколько кабелей (у VB-Audio есть
  дополнительные A+B, C+D). Мастер «Создать виртуальное устройство» проверяет, что есть, и ведёт
  по установке. Свой драйвер с созданием устройств «на лету» — отдельный большой проект после
  релиза (этап 8): понадобится EV-сертификат и подпись Microsoft (платно).

## 8. Сборка, подпись, безопасность публичного репозитория

- Автосборка в GitHub Actions на Windows-раннере. Сборка воспроизводима, версии зависимостей
  зафиксированы (Cargo.lock, package-lock).
- **В репозитории никогда нет ключей, сертификатов, токенов.** Подпись — внешний сервис
  SignPath; в GitHub лежит только токен в Secrets (не в коде и не в журналах).
- Секреты недоступны сборкам из чужих форков; для pull request подпись не выполняется.
- На GitHub аккаунте обязательна двухфакторная защита (требование SignPath).
- README содержит страницу «Политика подписи» с фразой: «Free code signing provided by
  SignPath.io, certificate by SignPath Foundation».
- До получения подписи: релизы без подписи + контрольные суммы SHA-256 + предупреждение в README.
- Установщик включает офлайн-установщик WebView2 (в сборках LTSC и пользовательских его может
  не быть). Драйверов в установщике нет; наличие виртуального кабеля проверяет само приложение.
- Все зависимости только с лицензиями, совместимыми с AGPL и принимаемыми SignPath (OSI):
  MIT, Apache-2.0, BSD, MPL-2.0, zlib и т.п. Никаких noncommercial/проприетарных.

## 9. Тестирование и диагностика

- Claude Code работает на компьютере пользователя: собирает, запускает, проверяет сам.
- Движок покрыть автотестами без железа: граф, суммирование, усиление, компиляция порядка.
- В приложении кнопка «Сохранить диагностику» (zip: журнал, версия Windows, список устройств,
  список аудиосессий, найден ли виртуальный кабель и WebView2, измеренная задержка). Нужна, чтобы пользователь
  мог отправить отчёт одним файлом.

## 10. Этапы

0. **Прототип «шаг 0»** (`docs/PROTOTYPE_STEP0.md`): проверка захвата звука процесса, устройств,
   виртуального кабеля и WebView2 на ПК пользователя.
1. Каркас: окно Tauri, карта с узлами без звука, сохранение, три языка, темы «Бимба» и «Метро».
2. Звук: устройства, захват приложения, громкость, суммирование, выход в наушники и в
   виртуальный микрофон, измерение задержки.
3. Кнопки: узел «Кнопка», круговой индикатор, кнопочная панель, простой режим.
4. Шаблоны, подсказки для новичка, мастер «установите виртуальный кабель», проверка задержки.
   *Как сделано:* «Проект → Шаблоны…» — четыре схемы (`app/ui/src/templates.ts`); шаблон
   добавляется ниже имеющейся схемы, ничего не стирая. «Проект → Виртуальный кабель…» — мастер:
   ищет обе стороны кабеля, при отсутствии показывает шаги установки с официального сайта (адрес
   только показывается и копируется, программа в сеть не ходит), при наличии — «Проверить
   связку» с замером задержки. При первом запуске — приветствие (`settings.welcomeDone`), на
   пустой карте — подсказка.
5. Установщик, автосборка, подпись, публикация, README ru/en/uk.
   *Как сделано:* установщик NSIS для текущего пользователя (без прав администратора), языки
   ru/en/uk, внутри офлайн-установщик WebView2 (≈ 211 МБ; маленький установщик без WebView2
   автор решил не делать). Автосборка GitHub Actions: лицензии, тесты, clippy, установщик,
   SHA-256; метка `vX.Y.Z` — черновик релиза. Подписи пока нет: в README — предупреждение и
   проверка SHA-256; заявку в SignPath подаёт автор, после одобрения добавим шаг подписи (токен —
   только в Secrets). Фразу «Free code signing provided by SignPath.io…» вписываем после одобрения.
6. Эффекты, морфер голоса и пресеты в простом режиме. Темы «Нео-нуар», «Инженерская».
   *Компрессор (сделан первым):* `crates/engine/src/compressor.rs` — feed-forward, уровень по
   громкому из каналов (стерео сжимается одинаково), мягкое колено 6 дБ, сглаживание в дБ,
   усиление меняется плавно внутри блока. Настройки меняются на лету (без перезапуска звука),
   сжатие показывается в боковой панели. Клавиша добавления — 5. Наборы подобраны по замеру
   голоса автора (`winaudio` тест `mic_level`): речь в среднем −32 дБ; прежние наборы (+6…12 дБ
   усиления) давали лишь +3…4 дБ, нынешние — около +10, +14 и +16 дБ.
   *Морфер голоса:* `crates/engine/src/morpher.rs` — по очереди сдвиг высоты (два скользящих
   отвода линии задержки с окном 40 мс; задержка ≈ 20 мс, пока высота изменена, иначе сигнал идёт
   мимо), кольцевая модуляция 55 Гц («робот»), полоса 450–2800 Гц с лёгким перегрузом («рация»),
   эхо 170 мс. Сила эффектов меняется плавно. Голоса — сочетания силы эффектов
   (`app/ui/src/morpher.ts`); они же — кнопки в простом режиме для каждого морфера на карте.
   Шаблон «Изменённый голос», клавиша добавления — 6. На ПК автора: 60 с без провалов, вся
   программа ≈ 3,5 % одного ядра. Дрожание: высота колеблется 7 раз в секунду до ±2 полутонов —
   на нём построен «Пришелец» (первая версия «выше + робот» автору не понравилась).
   *Щелчки в наушниках Virtual Desktop (2026-11-03):* тест `morpher_outputs` слушает выход в
   наушники через loopback. На «Speakers (Virtual Desktop Audio)» щелчки пачками в случайные
   моменты (0–700 за 20 с) даже у чистого тона нашим потоком без движка, при любом буфере (20 и
   100 мс); на VB-CABLE — 0. Причина в самом устройстве Virtual Desktop, не в SoundBimba.
   *Шумоподавление:* RNNoise (крейт `nnnoiseless`, BSD-3-Clause; `crates/engine/src/denoise.rs`),
   моно, кадры 10 мс, задержка 20 мс (кадр набора + кадр RNNoise, замерено). Сила смешивает
   очищенный звук с исходным, задержанным так же. Память выделяется при создании; FFT библиотеки
   заводит свои буферы при первом вызове в потоке — `Graph::warm_up` в потоке движка до начала
   цикла. Замер: гул вентилятора −52…59 дБ за 3 с, ровное белое шипение лишь −3…5 дБ. На ПК
   автора +1 % одного ядра. Шаблон «Чистый голос» (шумоподавление → компрессор).
   *Клавиши добавления узлов* — цифры 1–9 по порядку списка «Добавить узел»; сохранённые прежние

   Neue (SIL OFL) из программы.

   (медленно всплывают), панели и узлы — голубое стекло (`backdrop-filter`), белый текст,

7. Мониторинг и перенаправление приложений (недокументированные механизмы Windows — отдельно).
   *Как сделано (2026-11-03):* опыт `mute_original` показал, что заглушить программу в микшере
   Windows (`ISimpleAudioVolume`) нельзя — захват процесса снимает звук уже после громкости
   сессии, копия тоже пропадает. Поэтому «Оригинал звука» в узле «Звук приложения»: «Как обычно»,
   «На устройство» или «Только через SoundBimba» (оригинал — на устройство, которое не слушают).
   Это настройка Windows «Громкость приложений и устройства» через недокументированную фабрику
   WinRT `Windows.Media.Internal.AudioPolicyConfig` (`winaudio::routing`; порядок методов — как
   в EarTrumpet, проверен опытом `redirect_original` с разрешения автора). Факты опыта: Windows
   принимает настройку только у процесса, у которого уже есть звук (иначе E_INVALIDARG); уже
   играющий поток не переезжает — переезжает, когда программа заново открывает вывод; копия
   через захват процесса сохраняется. Приложение (`routes.rs`) применяет выбор раз в 2 с ко
   всем звучащим процессам программы, пишет журнал `routing.json` с прежним значением и
   возвращает его, когда выбор снят, узел удалён, звук выключен или SoundBimba закрывается;
   после аварийного закрытия — при следующем запуске, когда программа зазвучит. Сброс «у всех
   программ сразу» не используется. Журнал попадает в «Сохранить диагностику».
8. Свой драйвер (опционально, после релиза).

## 11. Риски

- Игры с защитой звука или античитом могут не отдавать звук процесса — принято.
- Зависимость от чужого закрытого кабеля (VB-CABLE): его могут изменить, сделать платным или
  перестать выпускать. Смягчение: поддерживаем любой кабель из списка, а не один; свой драйвер —
  этап 8.
- Кабель ставит пользователь: часть людей не справится. Нужен очень простой мастер с картинками
  и проверкой «кабель найден / связка работает».
- Подпись SignPath может быть отклонена для малого проекта; запасной план — релизы без подписи
  (или платный сертификат, если станет доступен).
- Антивирусы могут срабатывать на захват звука; помогает открытый код, воспроизводимая сборка
  и подпись.
- Пользовательская сборка Windows («SpicePC») может отличаться от стандартной: проверять на
  прототипе, не делать допущений.
- Сквозная задержка зависит от виртуального кабеля и захвата процесса: измерять на прототипе до
  обещаний.
- **Проверено на прототипе (2026-11-02), итоги этапа 0 — в `docs/PROTOTYPE_STEP0.md`:** захват
  звука процесса работает (браузер, 10 с без пропусков); связка VB-CABLE «динамик → микрофон»
  работает без искажений.
- **Запас захвата (2026-11-02, после этапа 4):** полторы порции устройства + блок движка (у
  микрофона с порцией 10 мс — 22 мс вместо 17). С целой порцией микрофон автора проваливался
  27 раз за 90 с (щелчки, слышные при разговоре), с полутора — 0. Цена — +5 мс задержки захвата.
- **Приоритет потоков устройств (2026-11-02):** потоки захвата и вывода, как и движок, работают
  с приоритетом MMCSS «Pro Audio». С обычным приоритетом вывод в наушники при схеме с кнопкой
  проваливался 60 раз за 45 с (Windows играла тишину), с MMCSS — 0 за 105 с. В журнал пишутся
  и провалы на стороне Windows («device gaps»: потеря данных при захвате, пустой буфер вывода);
  `cable_loop` ищет щелчки по каждому отсчёту.
- **Задержка (замер этапа 2, 2026-11-02):** SoundBimba → виртуальный микрофон ≈ 90 мс. Доля
  SoundBimba ≈ 20 мс (запасы 8/12 мс + порции устройств; вывод в режиме IAudioClient3 — буфер 280
  кадров вместо 1056), остальное (≈ 70 мс) — внутренний буфер VB-CABLE (он же дал 82 мс на этапе
  0 без SoundBimba). Цель < 30 мс с VB-CABLE по умолчанию недостижима. Варианты: уменьшить буфер в
  панели VB-CABLE (это делает сам пользователь; проверить, что звук не трещит), другой кабель,
  свой драйвер (этап 8). Пользователю показываем измеренную цифру (кнопка «Проверить задержку»).
