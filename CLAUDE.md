# CLAUDE.md — правила проекта SoundBimba

Сначала прочитай `docs/ARCHITECTURE.md`. Это источник истины. Если нужно отступить от него —
останови работу и спроси автора.

## Кто автор и как с ним общаться
- Автор **не программист**. Пиши ему по-русски, простыми словами, без жаргона. Коротко: что
  сделано, что проверить, что делать дальше.
- Не проси «открой терминал и выполни…», если можешь выполнить сам. Если нужно действие
  человека (поставить драйвер, нажать кнопку), давай нумерованную инструкцию по шагам.
- После каждого этапа: что теперь работает, как это проверить глазами, что не получилось.

## Железные правила
1. **Офлайн.** В программе нет сетевых запросов, телеметрии, внешних шрифтов и скриптов с CDN,
   автообновлений. Шрифты и ресурсы лежат в репозитории.
2. **Секреты.** Никаких ключей, сертификатов, токенов, паролей в репозитории и в журналах. Подпись
   только через SignPath и GitHub Secrets. Если нашёл секрет в коде — останови работу и сообщи.
3. **Лицензии.** Проект AGPL-3.0-or-later. Прежде чем добавить зависимость, проверь её лицензию:
   разрешены MIT, Apache-2.0, BSD, MPL-2.0, zlib, ISC, OFL (шрифты), Unicode-3.0 (добавлена
   автором 2026-11-02: нужна Tauri). Запрещены proprietary,
   noncommercial, GPL-2.0-only, любые «source-available». Каждую новую зависимость и ресурс
   (шрифты, иконки) записывай в `THIRD_PARTY_NOTICES.md`. В файлах кода короткий SPDX-заголовок:
   `SPDX-License-Identifier: AGPL-3.0-or-later`.
4. **GitHub.** Только публичный репозиторий; не используй приватные репозитории и платные
   функции GitHub (у автора региональные ограничения). Не предлагай обходить ограничения.
5. **Чужие драйверы не трогаем.** Виртуальный кабель (VB-CABLE и др.) ставит сам пользователь;
   мы его не встраиваем, не распространяем, не изменяем — только находим по названию устройств.
   Не предлагаем `testsigning` и отключение Secure Boot. (Решение от 2026-11-02, раздел 7
   архитектуры.)
6. **Горячие клавиши — только внутри окна SoundBimba.** Глобальных (системных) клавиш нет:
   они конфликтуют с играми и античитами. Все клавиши переназначаются или отключаются в окне
   «Клавиши» и не срабатывают в полях ввода. (Решение автора от 2026-11-02.)
7. **Не делай необратимого** (удаление файлов пользователя, смена системных настроек звука,
   установка драйвера) без явного подтверждения автора. Любое изменение настроек Windows —
   откатываемое и описанное в интерфейсе.
8. **Не придумывай факты о Windows-API.** Если не уверен — напиши маленький тест на реальной
   системе и покажи результат.

## Как работать
- Работай этапами из `docs/ARCHITECTURE.md` (раздел 10). Не перескакивай. Этап 0 — первым
  (`docs/PROTOTYPE_STEP0.md`).
- Небольшие коммиты, понятные сообщения по-русски или по-английски (как в репозитории), по
  одному смыслу на коммит. Не пушь в `main` сломанную сборку.
- Каждый этап заканчивается: сборка проходит, автотесты проходят, приложение запускается,
  автор получил короткую инструкцию «что проверить».
- Поток реального времени: без выделения памяти, блокировок и ввода-вывода внутри обработки.
- Весь видимый текст — через ключи локализации (`locales/ru|en|uk.json`). Никаких жёстко
  зашитых строк в компонентах.
- Весь цвет и вид — через переменные темы. Никаких цветов в компонентах.
- Интерфейс: тёмная тема «Бимба» по умолчанию, дружелюбно; карта должна оставаться
  аккуратной (автораскладка, мало текста на узлах, настройки в боковой панели).
- Диагностика: кнопка «Сохранить диагностику» появляется уже на этапе 1 и дополняется по мере
  роста.

## Команды (заполнить по мере появления)
- Нужно: Rust (MSVC), Visual Studio 2022 с C++ и **Windows 11 SDK** (без SDK нет kernel32.lib).
- Собирать из **PowerShell**, не из Git Bash: там `/usr/bin/link` подменяет компоновщик MSVC.
- Один раз после клонирования: `npm install` в папке `app`.
- Сборка приложения: в `app` выполнить `npx tauri build` → `target\release\soundbimba.exe`
  (установщик пока выключен: `bundle.active = false`, включим на этапе 5).
- Запуск для разработки: в `app` — `npx tauri dev`. Посмотреть интерфейс без Tauri (в браузере,
  с заглушкой вместо Rust): `npm run dev` в `app`, открыть http://localhost:5173.
- Тесты: `cargo test --workspace` и `npm test` (в `app`); стиль: `cargo clippy --workspace --all-targets`,
  типы: `npx tsc --noEmit` (в `app`).
- Лицензии: `node tools/licenses/check-cargo.mjs` (из корня) и `npm run licenses` (в `app`).
- Проба: `cargo build --release -p probe` → `target\release\probe.exe` (`--help`; без окна: `--no-pause`).
- Данные приложения: `%APPDATA%\SoundBimba\` — `project.json`, `settings.json`, `logs\soundbimba.log`.
